## Завершённые критерии этапа 0.3

### 1. Интерфейс DMA с заделом на IOMMU

Цель — дать драйверам единый безопасный способ получать память для обмена с устройствами, не связывая конкретный драйвер с текущей схемой физической памяти.

Критерии готовности:

- [x] отдельный `no_std`-интерфейс DMA;
- [x] явное различение процессорского виртуального адреса и адреса, видимого устройству;
- [x] проверяемые размеры, выравнивание и границы;
- [x] поддержка согласованного выделения/освобождения буфера без скрытой кучи на критическом пути (подтверждена двумя аппаратными обменами в QEMU без IOMMU; физические устройства ещё не проверялись);
- [x] возможность позднее подставить преобразование адресов IOMMU без изменения интерфейсов драйверов: `SplitDmaPlatform` разделяет физическую память и адресацию устройства, интеграционные испытания запускают один и тот же `DmaBuffer`-драйвер с прямым и нетождественным адресом устройства; **реальный IOMMU не реализован и не испытан**;
- [x] программная интеграционная проверка с текущим реестром драйверов (фиктивное устройство, без аппаратного DMA);
- [x] модульные проверки ошибочных размеров, переполнений и повторного освобождения;
- [x] обновление `STATUS.md` и `ROADMAP.md`.

**Дополнительные завершённые меры безопасности:**

- [x] при отказе освобождения DMA-области сохраняются владение, действующий идентификатор и возможность повторной попытки; добавлена проверка отказа и восстановления.

- [x] выделен отдельный обратимый программный контракт отображения физических адресов в адреса устройства; при ошибке снятия сохраняется действующее отображение, проверены повторная попытка и двойное снятие.

- [x] программная связка физических страниц, отображений процессора и устройства: прекращение доступа и последовательное освобождение, с испытаниями на системном распределителе и имитации отображений (без аппаратного DMA).

- [x] отображение выделенных физических страниц в зарезервированное окно ядра через существующий `ActivePageTable`: учёт частичного результата и восстановление после ошибок, с проверками на имитации таблиц страниц. Применение на физическом устройстве ещё не разрешено.

- [x] отдельный реестр непересекающихся виртуальных и физических DMA-окон фиксированной вместимости, защита от устаревших идентификаторов, запрет освобождения отображённых окон; флаги кэширования выбираются явно. Аппаратное подтверждение PAT/MTRR остаётся отдельной работой.

- [x] общий программный учёт виртуальных диапазонов ядра с резервированием DMA из того же пространства, откатом при отказе и запретом возврата окна до снятия отображений; испытания без аппаратного доступа.

**Проверка в ядре QEMU:**

- [x] Реальный программный цикл: выделение двух непрерывных физических страниц через системный распределитель, резервирование DMA-окна в общем реестре адресов, отображение страниц через активную таблицу, проверка содержимого через линейное отображение RAM, снятие отображений и возврат кадров данных. Промежуточные таблицы страниц остаются у ядра; второй проход подтверждает их повторное использование без дополнительного выделения. В этом испытании устройство не участвует; PAT/MTRR и аппаратная синхронизация DMA остаются открытыми.

- [x] ограниченный механизм прямой адресации DMA для QEMU без IOMMU: проверка допустимого диапазона, запрет пересекающихся активных отображений, контролируемое снятие и испытание с реальными выделенными страницами RAM в QEMU; аппаратный обмен пока не подтверждён.

**Промежуточный итог:** выполнено 8 из 8 программных и интерфейсных критериев DMA для проверенного QEMU-профиля, включая сменяемость адресного механизма без изменения драйвера. Аппаратная реализация IOMMU, PAT/MTRR и переносимость за пределы QEMU **не подтверждены** и остаются отдельными задачами. Реестр владения отслеживает активность, физический распределитель выдаёт непрерывные страницы с ограничением адресов, но полной связки с аппаратурой пока нет.

- [x] не добавлять BIOS/CSM: образ строится только `UefiBoot`, QEMU запускается через OVMF/pflash, `-nodefaults` и явный загрузочный NVMe-контроллер вместо неявного IDE; автоматические отрицательные проверки параметров;
