# Планировщик задач

На этапе 0.1 PhoenixOS отделяет алгоритм выбора следующей задачи от механизма переключения контекста. Это позволяет проверить политику планирования до появления полноценных потоков ядра.

## Модель

Библиотека `phoenix-scheduler` работает без стандартной библиотеки и не выделяет память динамически. Вместимость задаётся параметром типа при создании планировщика.

Для каждой задачи хранятся:

- числовой идентификатор;
- размер кванта в системных тиках;
- признак готовности к выполнению.

Алгоритм использует круговое обслуживание. На каждом системном тике он возвращает одно из решений:

- процессор может оставаться без работы;
- текущую задачу следует продолжить;
- следует переключиться с текущей задачи на другую.

Само сохранение регистров и переключение стека намеренно не входят в библиотеку. Они относятся к следующему пункту дорожной карты — потокам ядра.

## Операции

Планировщик поддерживает:

- добавление задачи;
- удаление задачи;
- блокировку и пробуждение задачи;
- получение текущей задачи;
- выбор следующей готовой задачи после исчерпания кванта;
- пропуск заблокированных задач;
- переход в состояние простоя, если готовых задач нет.

Ошибки переполнения, повторного идентификатора, неизвестной задачи и нулевого кванта возвращаются явно.

## Проверки

Модульные проверки подтверждают:

- смену задач после окончания кванта;
- пропуск заблокированных задач;
- выбор новой задачи после удаления текущей;
- обработку переполнения и ошибочных параметров;
- переход в простой, когда все задачи заблокированы.

Автоматическая проверка запускает `cargo test -p phoenix-scheduler`.

## Связь с таймером

Планировщик принимает абстрактные тики и не зависит от конкретного аппаратного таймера. На текущем x86-64 пути источником будущих вытесняющих событий служит периодический таймер локального x2APIC.

Такое разделение позволит позже заменить или откалибровать источник времени без изменения политики планирования.
