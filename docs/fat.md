# FAT — начальный слой

Модуль `phoenix-fat` начинает реализацию совместимого слоя FAT с безопасного разбора загрузочного сектора.

## Политика совместимости

FAT16 сохраняется только как режим чтения старых носителей. Разбор геометрии, чтение таблицы, цепочек, каталогов и файлов для FAT16 остаются доступными, но развитие полноценной записи FAT16 прекращено.

Записываемым форматом этого слоя является FAT32. Операции, которые меняют данные файла, запись каталога или таблицу FAT, проверяют тип тома до первой записи на устройство и для FAT16 возвращают явную ошибку `ReadOnlyFat16`.

FAT12 только распознаётся при разборе и не является целевым форматом. Основное хранилище PhoenixOS не должно строиться на FAT: этот модуль нужен для загрузочного раздела и совместимости с внешними носителями.

## Что проверяется

`FatBootSector::parse` принимает сектор размером не менее 512 байт и до использования геометрии проверяет:

- сигнатуру `0x55AA`;
- допустимый размер сектора 512/1024/2048/4096 байт;
- ненулевое степенное число секторов в кластере;
- резервную область и число таблиц FAT;
- наличие общего числа секторов и размера FAT;
- отсутствие арифметического переполнения;
- положение первого сектора данных;
- обязательный корневой кластер FAT32.

Тип FAT12/FAT16/FAT32 определяется по числу кластеров данных, а не по текстовой метке в загрузочном секторе.

## Чтение таблицы FAT

`FatTableReader` работает поверх общего `BlockDevice` и требует совпадения размера блока устройства с размером сектора FAT. Для FAT16 читается 16-разрядная запись, для FAT32 — 32-разрядная запись с маскированием верхних четырёх служебных битов.

Результат нормализуется в `FatEntry`: свободный кластер, ссылка на следующий кластер данных, резервное значение, повреждённый кластер или конец цепочки. Номера кластеров до 2 и значения за вычисленным диапазоном данных отклоняются до обращения к устройству.

FAT12 пока только распознаётся загрузочным парсером; чтение его 12-разрядных упакованных записей намеренно возвращает отдельную ошибку.

## Цепочки кластеров

`FatTableReader::read_chain` проходит цепочку FAT16/FAT32 в массив `u32`, переданный вызывающим кодом, поэтому не требует кучи. Каждый очередной номер проверяется на повторение; цикл возвращает `LoopDetected`. Если массив закончился раньше цепочки, возвращается `ChainBufferFull`, а свободная, повреждённая или резервная запись внутри цепочки считается ошибкой структуры.

Размер цепочки таким образом всегда ограничен ёмкостью буфера вызывающего кода, что исключает бесконечный обход повреждённого носителя.

## Каталоги

`FatTableReader::read_directory` читает фиксированный корневой каталог FAT16 и каталоги FAT32/дочерние каталоги через проверенные цепочки кластеров. Память внутри модуля не выделяется: вызывающий код передаёт массив для цепочки и секторный буфер.

Удалённые записи и служебные записи длинных имён пропускаются. Обычная запись возвращает короткое имя 8.3, атрибуты, первый кластер и размер файла. Обход можно завершить из вызываемой функции сразу после найденной записи.

Для получения длинных имён используется `read_directory_with_names`. Вызывающий код дополнительно передаёт рабочий буфер из `FAT_LONG_NAME_BUFFER_UNITS` элементов UTF-16. Последовательность служебных записей проверяется по порядковым номерам, служебным полям и контрольной сумме короткого имени. Состояние сохраняется при переходе между секторами и кластерами, поэтому длинное имя может пересекать их границу.

Если последовательность длинного имени повреждена, перепутана или относится к другой короткой записи, она не используется. Обычная запись каталога при этом всё равно выдаётся с именем 8.3. Это не позволяет повреждённым служебным данным подменить имя другого файла.

## Позиция записи каталога

`find_directory_entry` ищет обычную запись по её короткому имени 8.3 и возвращает метаданные вместе с непрямой позицией записи. Для FAT16 учитывается фиксированная корневая область, для FAT32 и дочерних каталогов сначала полностью проверяется цепочка кластеров.

Позиция содержит сектор и смещение внутри сектора, но её поля закрыты для внешнего кода. Штатно такую позицию можно получить только через поиск внутри модуля, поэтому последующий слой записи не будет принимать произвольный адрес на носителе.

Сам поиск ничего не изменяет на носителе. Следующий шаг повторно прочитает найденный сектор, проверит, что запись не была подменена, и только после этого разрешит изменить первый кластер и размер файла.

## Проверяемое обновление записи каталога

`update_file_directory_entry` принимает запись вместе с позицией, полученной через `find_directory_entry`. Перед изменением сектор читается заново, а текущая короткая запись полностью сравнивается с ранее найденной. Если имя, атрибуты, старый первый кластер или размер уже изменились, операция завершается до записи.

Метод работает только с обычными файлами. Для непустого файла новый первый кластер обязателен и проверяется по геометрии тома; для пустого файла допускается нулевой первый кластер.

После проверки меняются только поля первого кластера и размера файла. Имя, атрибуты, временные метки и остальные байты записи сохраняются. Для FAT32 обновляются старшая и младшая части номера кластера, затем сектор записывается и устройство фиксируется.

## Чтение файлов

`FatTableReader::read_file` принимает запись каталога, массив для цепочки кластеров, секторный буфер и буфер назначения. Для непустого обычного файла цепочка сначала полностью проверяется, после чего данные последовательно копируются из кластеров не дальше заявленного размера файла.

Если буфер назначения меньше размера файла, первый кластер отсутствует либо цепочка заканчивается раньше заявленного размера, возвращается явная ошибка. Пустой файл размером 0 байт читается без обращения к цепочке и допускает нулевой первый кластер.

## Запись в подготовленную цепочку

`write_prepared_chain` записывает содержимое файла только в уже зафиксированную новую цепочку FAT32. Перед первой записью метод проверяет размер буфера, вместимость цепочки и каждую ссылку FAT: очередной кластер должен ссылаться именно на следующий кластер из переданного плана, а последний — завершать цепочку.

Если цепочка изменилась после подготовки либо данных больше, чем она вмещает, запись не начинается. Это защищает от записи в кластеры, которые уже перестали соответствовать ожидаемому плану.

При успешной проверке метод последовательно перезаписывает все сектора подготовленной цепочки. Неиспользованный хвост последнего сектора и лишних кластеров обнуляется, чтобы в новом файле не сохранялись прежние байты носителя. После завершения устройство фиксируется.

## Запись внутри существующей цепочки

`FatTableReader::write_file_in_place` изменяет только байты внутри уже существующего размера обычного файла FAT32. Перед первой записью модуль проверяет границы операции, полностью проходит цепочку FAT и убеждается, что выделенных кластеров достаточно для заявленного размера файла.

Частичная запись использует чтение-изменение-запись целого сектора, поэтому соседние байты сохраняются. Операция может пересекать границы секторов и кластеров. После завершения вызывается фиксация блочного устройства.

Метод намеренно не увеличивает размер файла, не меняет запись каталога и не выделяет новые кластеры. Если питание пропадёт во время нескольких секторных записей, часть данных уже может быть изменена: атомарность и журналирование будут решаться на более высоком уровне либо в собственной файловой системе.

## Изменение таблицы FAT

`find_free_cluster` последовательно ищет первый свободный кластер начиная с указанной позиции и проверяет каждую запись через тот же безопасный разбор таблицы.

`write_fat_entry` изменяет одну запись FAT32 во всех копиях таблицы. FAT16 на этом уровне доступен только для чтения и отклоняется до первой записи. Ссылка на следующий кластер предварительно проверяется по фактической геометрии тома. Для FAT32 верхние четыре служебных бита каждой копии сохраняются, а свободная запись, повреждённый кластер и конец цепочки кодируются штатными значениями формата. Резервные значения напрямую записывать нельзя.

После обновления всех копий вызывается фиксация блочного устройства. Этот уровень пока не является транзакцией: сбой устройства между обновлениями зеркальных таблиц может оставить копии FAT различающимися, поэтому построение цепочек будет добавлено отдельным протоколом с проверкой и восстановлением.

## Планирование новой цепочки

`plan_free_clusters` подбирает заданное число свободных кластеров в массив, переданный вызывающим кодом, но не меняет таблицу FAT. Поиск начинается с указанного кластера, доходит до конца допустимого диапазона и один раз продолжает с начала области данных.

Если рабочего массива недостаточно либо на томе нет требуемого числа свободных кластеров, изменение носителя не происходит. Полученный список является только планом: до отдельной фиксации любой из найденных кластеров всё ещё считается свободным.

Разделение поиска и записи нужно для будущего протокола выделения: сначала система должна доказать, что место для полной новой цепочки существует, и только потом начинать менять таблицу.

## Фиксация новой цепочки

`commit_planned_chain` принимает заранее подготовленный список кластеров. До первой записи метод проверяет весь список: каждый кластер должен существовать, не повторяться и оставаться свободным.

После полной проверки цепочка фиксируется с хвоста к голове: последний кластер сначала получает признак конца цепочки, затем предыдущие кластеры последовательно начинают ссылаться на уже подготовленный хвост. Старая цепочка и запись каталога на этом этапе не изменяются.

Если устройство откажет во время фиксации, уже записанные новые кластеры могут остаться осиротевшими и потребовать последующего освобождения. Такой сбой не должен перенаправлять существующий файл на неполную цепочку, потому что переключение записи каталога выполняется отдельным будущим шагом.

## Освобождение отключённой цепочки

`free_detached_chain` предназначен только для цепочки, на которую уже не ссылается актуальная запись каталога. Перед первой записью метод полностью проходит старую цепочку тем же проверенным механизмом, включая обнаружение циклов и повреждённых записей.

Только после успешной проверки все кластеры цепочки последовательно помечаются свободными. Если исходная цепочка повреждена, освобождение вообще не начинается.

При отказе устройства во время освобождения часть старых кластеров может остаться занятой и потребовать последующей очистки, но активная новая цепочка от этого не изменяется. Поэтому порядок операции принципиален: сначала новая цепочка, затем переключение метаданных каталога, и только после этого освобождение старой.

## Единая замена содержимого файла

`replace_file_contents` объединяет безопасный порядок полной замены обычного файла FAT32 в одну операцию. До изменения носителя проверяются тип тома, запись файла и существующая старая цепочка.

Для непустого нового содержимого порядок фиксирован: подобрать свободные кластеры, зафиксировать новую цепочку, записать и проверить данные новой цепочки, повторно сверить запись каталога, переключить её на новую цепочку и только после этого освобождать старую. Для пустого содержимого запись каталога сначала переключается на пустой файл, после чего старая цепочка освобождается.

Если ошибка возникает до переключения записи каталога, старый файл остаётся активным. Уже подготовленная новая цепочка при аппаратном сбое может остаться осиротевшей; это безопаснее автоматического отката, который способен скрыть исходную ошибку устройства. Если ошибка возникает при освобождении старой цепочки уже после переключения каталога, `OldChainCleanupFailed` возвращает активную новую запись вместе с ошибкой очистки: новый файл уже считается действующим, а старые кластеры требуют последующей проверки свободного места.

Операция не выделяет память в куче. Один переданный массив кластеров используется сначала для проверки старой цепочки и планирования новой, а после переключения может быть повторно использован при освобождении старой.

## Ограничения

Длинные имена возвращаются как проверенные единицы UTF-16; преобразование в кодировку пользовательского интерфейса остаётся задачей более высокого слоя. Низкоуровневые операции FAT32 уже собраны в единый порядок полной замены существующего файла, но создание новых записей каталога, расширение каталогов и восстановление осиротевших цепочек остаются отдельными задачами совместимого слоя. FAT16 остаётся только режимом чтения, FAT12 распознаётся, но его поддержка не заявляется как целевая.

Следующий шаг — отдельное атомарно-подобное переключение записи каталога на уже подготовленную новую цепочку. Только после такого переключения старая цепочка может передаваться в `free_detached_chain`.
