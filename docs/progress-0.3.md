## Первый практический результат xHCI

После добавления `qemu-xhci` в проверочный профиль ядро действительно вывело `xhci pcie discovery: OK` с контроллером 1b36:000d по адресу BAR0 `0x380000000000`. Полная проверка загрузки QEMU завершилась успешно. Это проверка обнаружения на модели устройства QEMU, а не передача данных через DMA. Основной пункт «обнаружение через PCIe и реестр драйверов» остаётся открытым до подключения штатного драйвера к реестру.

## Практический переход к xHCI

- [x] Разбор регистров возможностей xHCI и проверка диапазонов BAR с имитацией регистров; без аппаратного MMIO.
- [x] Чтение регистров xHCI из отдельного некэшируемого MMIO-отображения в QEMU, проверка возможностей и последующее снятие отображения.
- [x] Остановка и аппаратный сброс xHCI в QEMU; после сброса контроллер готов и остаётся остановленным. Есть проверка таймаутов и состояний.
- [x] Инициализация DCBAA, командного и событийного колец, запуск, две команды No Op и события завершения через DMA в QEMU с безопасным возвратом страниц.

Пункт разбора регистров является внутренней частью незавершённого направления xHCI; основные показатели увеличились до **15/43**, DMA — **7/8**, подробные DMA — **15/17**, xHCI — **5/7** по проверенному профилю QEMU.

## Следующее задание

Следующий результат xHCI — подключение драйвера к общему реестру и проверка портов/перечисления USB-устройств. Для DMA отдельно проверить PAT/MTRR, псевдонимы физической памяти и подготовить испытания на разрешённом физическом оборудовании. Общесистемное закрепление DMA-окон и проверка PAT/MTRR остаются отдельными требованиями. Не создавать второй физический распределитель. Пока физические устройства и раздел Windows не трогать.
