## Первый практический результат xHCI

После добавления `qemu-xhci` в проверочный профиль ядро действительно вывело `xhci pcie discovery: OK` с контроллером 1b36:000d по адресу BAR0 `0x380000000000`. Полная проверка загрузки QEMU завершилась успешно. Это проверка обнаружения на модели устройства QEMU, а не передача данных через DMA. Основной пункт «обнаружение через PCIe и реестр драйверов» закрыт: реестр выбирает xHCI по классу PCIe и запускает его с явным контекстом памяти ядра.

## Практический переход к xHCI

- [x] Реестр выбирает драйвер xHCI по классу PCIe, передаёт ему ресурсы ядра и подтверждает запуск после чтения регистров и аппаратных DMA-операций в QEMU; проверка загрузки требует нового признака `xhci driver registry start: OK`.
- [x] Разбор регистров возможностей xHCI и проверка диапазонов BAR с имитацией регистров; без аппаратного MMIO.
- [x] Чтение регистров xHCI из отдельного некэшируемого MMIO-отображения в QEMU, проверка возможностей и последующее снятие отображения.
- [x] Остановка и аппаратный сброс xHCI в QEMU; после сброса контроллер готов и остаётся остановленным. Есть проверка таймаутов и состояний.
- [x] Инициализация DCBAA, командного и событийного колец, запуск, по команде No Op и реальные события завершения через DMA в QEMU с безопасным возвратом страниц.
- [x] Сканирование всех портов xHCI, проверка подключения, скорости и активности, безопасный сброс отключённых портов. В QEMU проверяются USB-клавиатура и мышь как два подключения к модели контроллера; получение дескрипторов выполняется через DMA, а обработка HID-событий реализована в последующих этапах ниже.

После подключения действующего обработчика к реестру основные показатели составляют **18/43**, DMA — **7/8**, подробные DMA — **15/17**, xHCI — **7/7** по проверенному профилю QEMU.

## Жизненный цикл работающего xHCI

- [x] Контекст драйвера сохраняет владение MMIO-окном и 12 страницами DMA после первоначального перечисления USB.
- [x] Через реестр драйверов ядро получает работающий экземпляр, который переживает остальные системные самопроверки.
- [x] После завершения проверок ядра без повторного сброса выполняются опросы состояния контроллера и кольца событий (на стабильном QEMU-профиле новых событий нет).
- [x] Безопасная явная остановка возвращает 12 физических страниц и снимает MMIO-отображение; проверяется загрузочным признаком.
- [x] Действительная смена состояния USB в QEMU: удаление клавиатуры через монитор, событие отключения и команда Disable Slot, повторное подключение на другом порту и назначение адреса без сброса xHCI; мышь сохраняет слот.
- [x] Служба на отдельном аппаратно вытесняемом потоке с независимым потоком управления, неограниченным рабочим циклом и экономным ожиданием x2APIC; второй QEMU-сценарий подтвердил переподключение, HID-ввод, передачу событий, запрос остановки, завершение потоков и возврат всех 12 DMA-страниц.

Подзадачи жизненного цикла xHCI: **6/6**, прирост **+1 подзадача**. Рабочая служба и управляющий поток были переключены системным планировщиком в QEMU (контроль не менее 64 тиков второго потока и фиксируемые периоды ожидания без холостого опроса). Поддержка физического ноутбука, обработка реальных аппаратных прерываний xHCI вместо периодического опроса и полноценная длительная интерактивная сессия пока не проверялись.

## Аппаратные USB HID-отчёты (QEMU)

- [x] Разбор загрузочных USB-дескрипторов клавиатуры и мыши, включая адрес IN-точки, размер пакета и период опроса.
- [x] Команда Configure Endpoint и управляющий запрос SET_CONFIGURATION подтверждены действующим контроллером QEMU.
- [x] Два независимых кольца прерываний IN и собственные буферы отчётов без дополнительных DMA-страниц; сохраняются 12 страниц от предыдущего шага.
- [x] Клавиатура: получены действительные нажатие и отпускание «A», типизированные изменения HID; модульные проверки нескольких одновременных клавиш и модификаторов.
- [x] Мышь: получены настоящие относительные смещения X=12, Y=-6; модульный разбор кнопок, колеса, знаковых смещений; отпускание кнопки не отфильтровывается.
- [x] Действительные события переподключения USB продолжают работать; единое кольцо событий не теряет завершения HID во время команд, аппаратная память возвращается после остановки.
- [x] Единый путь доставки событий HID в очередь ядра и пользовательские приложения, включая штатную командную оболочку, подтверждён двумя отдельными ELF-процессами в QEMU; непрерывная работа USB из планировщика остаётся самостоятельным незакрытым пунктом xHCI.

По USB HID основные критерии: **5/5**; xHCI: **7/7**, DMA: **7/8**, этап 0.3: **22/43**. Семь подробных подпунктов аппаратного USB HID теперь выполнены на **7/7** с учётом доставки в приложения. На момент первого испытания USB HID служба планировщика ещё не была подключена; позднее она успешно проверена во втором цикле QEMU (см. раздел «Служба xHCI в аппаратном планировщике ядра»). Физические устройства и аппаратное IOMMU по-прежнему не проверены.

## Системная очередь и пользовательский ввод (QEMU)

- [x] Общее 48-байтовое представление клавиши, мыши и смены подключения с последовательным номером и счётчиком потерянных событий.
- [x] Ограниченная системная очередь без выделения памяти; при заполнении удаляется старейшая запись, потеря отмечается явно, порядок проверен модульными испытаниями.
- [x] Настоящие извещения от xHCI (отключение и подключение, нажатие и отпускание «A», движение мыши) поступают в единую очередь.
- [x] Системный вызов чтения проверяет право `Device + READ` из таблицы возможностей процесса, а не только переданный номер.
- [x] Проверка адреса, выравнивания, длины и всей пользовательской памяти происходит до удаления события; неверный указатель и отсутствие права проверяются без потери записи.
- [x] Пользовательская библиотека и команда оболочки `input` получают записи с номером последовательности и счётчиком потерь.
- [x] Две различные пользовательские программы ELF в QEMU: первая читает четыре события USB, вторая (штатная оболочка) считывает оставшееся движение мыши через системный вызов. После завершения очередь пуста, ресурсы возвращены.

Подзадачи очереди: **7/7**. Самостоятельный критерий USB HID закрыт, поэтому этап **22/43 (51,2 %)**, USB HID **5/5**. Испытана конечная последовательность в QEMU, не постоянная фоновая служба на оборудовании.

## Служба xHCI в аппаратном планировщике ядра

- [x] Контроллер USB имеет единственный поток-владелец; ни один другой поток не изменяет его MMIO, слоты или DMA во время обслуживания.
- [x] Тот же аппаратный планировщик x2APIC, уже использовавшийся для испытания вытеснения, теперь исполняет настоящую службу USB и отдельный поток управления.
- [x] Служба не имеет предельного количества итераций: при отсутствии событий поток ожидает следующий аппаратный тик, не занимая процессор пустым циклом.
- [x] События отключения/подключения устройства, восстановление HID-точки, нажатие/отпускание клавиши B и перемещение мыши (X=7, Y=5) обработаны во втором цикле QEMU.
- [x] События второго цикла направляются в ту же защищённую системную очередь ввода; запись и чтение очереди защищены от вытеснения внутри критического участка.
- [x] Независимый поток направляет явный запрос остановки после аппаратных событий. Отказ службы переводит её в отдельное аварийное состояние; освобождение DMA при неясном состоянии запрещено.
- [x] Распорядитель дожидается завершения обоих потоков, отключает обработчик аппаратного планирования, очищает их стеки и лишь затем останавливает xHCI и возвращает 12 DMA-страниц.

Контрольные признаки аппаратной проверки: `xhci scheduled ready: OK`, `xhci scheduled detached: OK`, `xhci scheduled attached: OK`, `xhci scheduled key pressed: OK`, `xhci scheduled key released: OK`, `xhci scheduled mouse moved: OK`, `xhci scheduled stop requested: OK`, `xhci scheduled stopped: OK`, `xhci scheduled lifecycle: OK`, `xhci scheduled concurrent: OK` и `xhci scheduled dma shutdown: OK`.

**Подзадачи этого цикла: 7/7. Жизненный цикл xHCI: 6/6 (ранее 5/6).** Основной счёт этапа остаётся **22/43 (51,2 %)**: общие критерии xHCI уже учитывались как 7/7, дополнительная проверка не должна дважды увеличивать общий счёт. Испытания проходили в конечном контрольном профиле QEMU; это не подтверждает физические контроллеры, IOMMU и постоянно работающую графическую оболочку.

## Следующее задание

Следующий результат — выбрать первый поддерживаемый физический графический профиль для штатного драйвера и сформировать критерии проверки. PhoenixFS поверх NVMe проверяется в QEMU; длительная работа системного тома и физическое оборудование не заявляются готовыми. Ввод в постоянно работающую интерактивную оболочку остаётся отдельной системной задачей; служба xHCI из планировщика уже реализована. Для DMA отдельно проверить PAT/MTRR, псевдонимы физической памяти и подготовить испытания на разрешённом физическом оборудовании. Общесистемное закрепление DMA-окон и проверка PAT/MTRR остаются отдельными требованиями. Не создавать второй физический распределитель. Пока физические устройства и раздел Windows не трогать.
