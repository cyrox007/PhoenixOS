# Управление памятью

Подсистема памяти PhoenixOS вводится по слоям, чтобы каждый этап можно было проверить до передачи ему большей ответственности.

## Начальный распределитель

Первый распределитель использует только области, помеченные загрузчиком как `Usable`.

Свойства:

- не требует кучи;
- размер физической страницы — 4 КиБ;
- выдаёт страницы последовательно;
- пропускает недоступные области;
- выравнивает начало области до границы страницы;
- не освобождает страницы;
- предназначен только для самых ранних стадий загрузки.

Он сохраняется как минимальный инструмент начальной загрузки, но не предназначен для долговременного управления памятью.

## Системный распределитель физической памяти

Следующий слой — `SystemFrameAllocator`.

Он хранит свободную память в виде упорядоченных диапазонов физических страниц и уже умеет:

- выдавать страницы по 4 КиБ;
- возвращать страницы;
- повторно использовать освобождённые страницы;
- объединять соседние свободные диапазоны;
- отличать двойное освобождение от корректного возврата;
- отвергать страницы, которые не принадлежат управляемой памяти;
- работать без кучи;
- реализовывать стандартные интерфейсы `FrameAllocator` и `FrameDeallocator` библиотеки `x86_64`.

Количество служебных записей ограничивает только степень фрагментации списка диапазонов, а не общий объём ОЗУ.

На раннем этапе поиск линейный по числу свободных диапазонов. Это осознанный выбор в пользу простой проверяемой реализации без преждевременного усложнения. После появления реальных нагрузок распределитель можно заменить на buddy-схему или гибрид, сохранив внешний интерфейс.

## Владение физической памятью

Для набора свободных областей должен существовать один владелец распределения.

Нельзя одновременно использовать начальный и системный распределители над одной и той же картой памяти без явной передачи уже занятых страниц: иначе одна физическая страница может быть выдана повторно.

Целевой путь загрузки — как можно раньше передать управление физической памятью системному распределителю и далее использовать его как единственный источник свободных страниц.

## Ошибки, которые проверяются явно

Системный распределитель различает:

- исчерпание служебных записей диапазонов;
- двойное освобождение;
- попытку вернуть страницу за пределами управляемой памяти.

Нарушение контракта низкоуровневого `FrameDeallocator` считается ошибкой ядра.

## Следующий этап — виртуальная память

После стабилизации физического распределения:

1. исследовать активные таблицы страниц после загрузки;
2. создать безопасные операции отображения и снятия отображения;
3. зафиксировать схему виртуального адресного пространства ядра;
4. отобразить кучу ядра;
5. добавить защитные страницы;
6. создать адресные пространства процессов;
7. позднее добавить копирование при записи и общую память.

## Проверки

Модульные тесты покрывают:

- подсчёт карты памяти;
- пропуск зарезервированных областей;
- невыровненные начала;
- исчерпание начального распределителя;
- переход между разделёнными свободными областями;
- выдачу, освобождение и повторное использование страницы;
- объединение соседних диапазонов;
- двойное освобождение;
- возврат чужой страницы;
- объединение соседних исходных областей;
- нехватку служебных записей при сильной фрагментации.

Проверочная загрузка QEMU должна дополнительно подтверждать работу системного распределителя на реальной карте памяти UEFI до перехода к виртуальной памяти.
