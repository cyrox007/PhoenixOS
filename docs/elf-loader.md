# Загрузчик ELF64

Первый инкремент этапа 0.2 вводит отдельный `no_std`-модуль `phoenix-elf-loader` для безопасного разбора исполняемых файлов ELF64 на x86-64.

## Поддерживаемый формат

Разборщик принимает ELF64 с порядком байтов little-endian, текущей версией ELF и архитектурой x86-64. Поддерживаются типы `ET_EXEC` и `ET_DYN`; фактическое размещение позиционно-независимого образа и релокации пока не выполняются.

Заголовок программы проверяется до чтения таблицы сегментов. Для каждой записи `PT_LOAD` проверяются:

- границы таблицы программных заголовков;
- отсутствие переполнений адресов и размеров;
- условие `filesz <= memsz`;
- принадлежность файловой части образу;
- степенное выравнивание;
- согласованность смещения файла и виртуального адреса по выравниванию.

Разборщик не выделяет динамическую память и возвращает итератор по загружаемым сегментам. Это позволяет следующему слою ядра самостоятельно создавать пользовательские отображения и переносить данные в `ProcessAddressSpace`.

## Граница текущего инкремента

Этот шаг намеренно не отображает сегменты в адресное пространство процесса и не передаёт управление пользовательской программе. Следующий инкремент должен связать `PT_LOAD` с `ProcessAddressSpace`, преобразовать флаги ELF в права страниц и проверить нулевое заполнение диапазона `memsz - filesz`.

После этого можно будет добавить запуск ELF-образа через уже существующий пользовательский цикл CPL3/SYSCALL/SYSRET.
