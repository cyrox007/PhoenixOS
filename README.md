# PhoenixOS

PhoenixOS — операционная система, создаваемая с нуля для современных компьютеров x86-64.

Долгосрочная цель — полноценная настольная платформа общего назначения: ядро, драйверы, сеть, графическая среда, комплект разработки, экосистема приложений, пакеты и обновления, браузер, документация и встроенные приложения.

## Текущее состояние

Текущий активный этап — **0.3 «Устройства и драйверы»**.

Этапы 0.0 «Начальная загрузка», 0.1 «Основы ядра» и 0.2 «Хранилище и пользовательское пространство» завершены по текущей дорожной карте.

В 0.3 уже реализованы:

- проверяемое обнаружение платформы через ACPI;
- перечисление PCIe через ECAM;
- реестр драйверов, подбор подходящего драйвера, запуск и контроль версии.

Ближайшая плановая задача — **интерфейс DMA с заделом на IOMMU**. После него по плану идут xHCI, USB HID, NVMe, полноценный графический драйвер, эталонный драйвер для комплекта разработки и удаление рабочих зависимостей от устаревших аппаратных путей.

Актуальная последовательность работ поддерживается в [TASKS.md](TASKS.md), общий план выпусков — в [ROADMAP.md](ROADMAP.md), подробная история реализованных подсистем — в [STATUS.md](STATUS.md).

## Текущие целевые решения

- архитектура процессора: x86-64;
- загрузка: UEFI;
- эталонная виртуальная платформа: QEMU + OVMF;
- ядро: Rust в режиме `no_std`, с небольшими явно выделенными участками низкоуровневого и ассемблерного кода;
- публичный интерфейс приложений: стабильный C-совместимый ABI, поверх которого строятся привязки для языков;
- устройство ядра: модульное гибридное ядро;
- стратегия оборудования: сначала небольшой проверенный перечень современных устройств, затем расширение через документированный комплект разработки драйверов;
- постоянное хранилище: PhoenixFS поверх общего блочного слоя, с поколениями, копированием при записи, восстановлением и контролем целостности пользовательских данных;
- внешние носители: явная политика защищённого и открытого доступа на границе блочного ввода-вывода;
- пользовательское пространство: ELF64, процессы, службы, файловые дескрипторы, базовая совместимость libc и пакетная командная оболочка;
- сеть: IPv4 + IPv6, сокеты, DHCP/SLAAC, DNS, TCP/UDP, TLS, HTTP(S), прокси, сначала Ethernet, затем Wi-Fi через общую модель драйверов;
- браузер: перенос готового современного движка стандартов; собственные HTML/CSS/JavaScript-движки с нуля не планируются;
- обновления: подписанные транзакционные обновления системы и приложений с откатом, восстановлением, каналами и поэтапным распространением.

## Ветки

- `main` — стабильные точки интеграции;
- `develop` — основная ветка разработки;
- `feature/*` — изолированные небольшие изменения.

Обычный путь изменения: отдельная ветка → запрос на слияние в `develop` → профильные проверки → полная автоматическая проверка → слияние.
