## Ближайшая задача

### 1. Интерфейс DMA с заделом на IOMMU

Цель — дать драйверам единый безопасный способ получать память для обмена с устройствами, не связывая конкретный драйвер с текущей схемой физической памяти.

Критерии готовности:

- [x] отдельный `no_std`-интерфейс DMA;
- [x] явное различение процессорского виртуального адреса и адреса, видимого устройству;
- [x] проверяемые размеры, выравнивание и границы;
- [x] поддержка согласованного выделения/освобождения буфера без скрытой кучи на критическом пути (подтверждена двумя аппаратными обменами в QEMU без IOMMU; физические устройства ещё не проверялись);
- [ ] возможность позднее подставить преобразование адресов IOMMU без изменения интерфейсов драйверов;
- [x] программная интеграционная проверка с текущим реестром драйверов (фиктивное устройство, без аппаратного DMA);
- [x] модульные проверки ошибочных размеров, переполнений и повторного освобождения;
- [x] обновление `STATUS.md` и `ROADMAP.md`.

**Дополнительные завершённые меры безопасности:**

- [x] при отказе освобождения DMA-области сохраняются владение, действующий идентификатор и возможность повторной попытки; добавлена проверка отказа и восстановления.

- [x] выделен отдельный обратимый программный контракт отображения физических адресов в адреса устройства; при ошибке снятия сохраняется действующее отображение, проверены повторная попытка и двойное снятие.

- [x] программная связка физических страниц, отображений процессора и устройства: прекращение доступа и последовательное освобождение, с испытаниями на системном распределителе и имитации отображений (без аппаратного DMA).

- [x] отображение выделенных физических страниц в зарезервированное окно ядра через существующий `ActivePageTable`: учёт частичного результата и восстановление после ошибок, с проверками на имитации таблиц страниц. Применение на физическом устройстве ещё не разрешено.

- [x] отдельный реестр непересекающихся виртуальных и физических DMA-окон фиксированной вместимости, защита от устаревших идентификаторов, запрет освобождения отображённых окон; флаги кэширования выбираются явно. Аппаратное подтверждение PAT/MTRR остаётся отдельной работой.

- [x] общий программный учёт виртуальных диапазонов ядра с резервированием DMA из того же пространства, откатом при отказе и запретом возврата окна до снятия отображений; испытания без аппаратного доступа.

**Проверка в ядре QEMU:**

- [x] Реальный программный цикл: выделение двух непрерывных физических страниц через системный распределитель, резервирование DMA-окна в общем реестре адресов, отображение страниц через активную таблицу, проверка содержимого через линейное отображение RAM, снятие отображений и возврат кадров данных. Промежуточные таблицы страниц остаются у ядра; второй проход подтверждает их повторное использование без дополнительного выделения. В этом испытании устройство не участвует; PAT/MTRR и аппаратная синхронизация DMA остаются открытыми.

- [x] ограниченный механизм прямой адресации DMA для QEMU без IOMMU: проверка допустимого диапазона, запрет пересекающихся активных отображений, контролируемое снятие и испытание с реальными выделенными страницами RAM в QEMU; аппаратный обмен пока не подтверждён.

**Промежуточный итог:** выполнено 7 из 8 критериев интерфейса DMA для проверенного QEMU-профиля. Не закрыто подтверждение сменяемого отображения через IOMMU на аппаратном уровне и переносимость за пределы проверенного QEMU-профиля. Реестр владения отслеживает активность, физический распределитель выдаёт непрерывные страницы с ограничением адресов, но полной связки с аппаратурой пока нет.

  - [x] подключить некэшируемое отображение MMIO и проверить регистры действующего контроллера в QEMU;
- [x] остановка/сброс/запуск контроллера (QEMU, с подготовленными структурами DMA);
  - [x] остановка, аппаратный сброс и ожидание готовности xHCI в QEMU; ограничение ожиданий и модульные проверки отказов;
  - [x] запуск после подготовки структур DMA (DCBAA, командного и событийного колец);
- [x] командное и событийное кольца (первая команда No Op и подтверждение завершения в QEMU);
- [x] базовая работа с портами: обнаружение подключения, состояния и скорости, управляемый сброс, проверка двух устройств в QEMU;
- [x] использование общего DMA (системный распределитель, ограниченная прямая адресация и безопасное освобождение в QEMU);
- [x] проверка под QEMU q35 (два последовательных DMA-обмена с событием завершения и возвратом памяти).

**Продолжение после регистрации:**

- [x] два USB-устройства в одном запущенном сеансе xHCI: собственные контексты и кольца EP0, два разных слота, повторное чтение конфигурации первого устройства после перечисления второго без промежуточного сброса; все страницы DMA возвращаются после остановки контроллера (QEMU).
- [x] работающий экземпляр xHCI удерживает отображение регистров MMIO, две адресованные USB-конфигурации и 12 DMA-страниц в течение остальных проверок ядра; доступен опрос кольца событий порта без повторного запуска контроллера. Проверяется после основной загрузки QEMU.
- [x] явное безопасное завершение: аппаратная остановка и сброс → снятие DMA-отображения → возврат страниц → снятие MMIO, с защитой от повторного завершения; при отказе остановки DMA не освобождается.
- [x] обработка настоящих событий отключения и повторного подключения USB-клавиатуры в работающем xHCI: подтверждение PORTSC, аппаратная команда Disable Slot, повторная адресация через освобождённый контекст и проверка сохранности слота USB-мыши; интеграционный QEMU с управлением устройством через монитор.
- [x] циклическое продвижение командного и событийного колец, сохранение событий портов во время ожидания команд и блокировка опасного повторного использования DMA при сбое.
- [x] постоянная служба xHCI под аппаратным планировщиком ядра (проверено в QEMU): собственный поток без ограничителя итераций, второй поток контроля, ожидание таймера без непрерывного опроса, обработка повторного переподключения и HID-отчётов, атомарное уведомление об отказе, остановка по явному запросу, освобождение DMA/MMIO только после прекращения работы потоков. Проверка на физическом оборудовании и обычная длительная интерактивная сессия ОС остаются отдельными этапами.

### 3. USB HID

- [x] USB-мышь в QEMU: Configure Endpoint и SET_CONFIGURATION, отчёты прерываний IN, реальное движение X/Y из монитора QEMU, разбор кнопок и колеса, передача отпускания кнопки при нулевом смещении.
- [x] общая модель событий ввода на уровне ОС в проверочном QEMU: ограниченная очередь с учётом переполнений, полномочия Device/READ и безопасный системный вызов чтения; настоящие USB-события доставлены двум отдельным пользовательским ELF-процессам, включая командную оболочку. ### 4. NVMe

- [x] обнаружение NVMe-контроллера через PCIe/ECAM в QEMU: проверка класса 01:08:02 и BAR, выбор драйвера общим реестром, безопасный снимок CAP/VS/CC/CSTS через временное MMIO без записи и без использования накопителя; защита от неверных регистров и модульные испытания;
- [x] административные очереди NVMe через общий DMA в QEMU: две очереди глубиной 16, три закреплённые страницы (подача, завершения, ответ), настройка AQA/ASQ/ACQ/CC, подтверждение CSTS.RDY, две настоящие команды Identify Controller/Namespace, проверка номера команды, фазы, очереди и кода завершения, остановка и возврат всех страниц (очереди чтения/записи реализованы последующими пунктами);
- [x] чтение/запись блоков NVMe в QEMU: создание рабочих очередей через общий DMA, пять аппаратных команд на последнем логическом блоке временного накопителя (чтение, запись, сверка, восстановление, повторная сверка), проверка фазы/номера/кода завершения, возврат 6/6 DMA-страниц после подтверждённой остановки (общий блочный интерфейс реализован следующим пунктом); физическое оборудование отдельно;
- [x] подключение NVMe к `phoenix-block::BlockDevice` в QEMU: геометрия пространства имён, многоблочное чтение/запись с разбиением по 4 КиБ, настоящая команда принудительной фиксации, проверка неверной длины и выхода за LBA, остановка операций при ошибке очереди, 17 завершённых аппаратных команд через очередь глубиной 16 и восстановление исходных данных 10 блоков; экземпляр пока живёт лишь в проверочном сеансе, постоянная служба и PhoenixFS отдельно;
- [x] проверка ошибок и таймаутов NVMe: общий ограниченный опрос готовности и завершений для административных и рабочих очередей, проверка `CSTS.CFS` и потери `CSTS.RDY` на каждом шаге, обнаружение отсутствия нужной фазы, изоляция рабочей очереди после ошибки, проверочные модели зависания, отказа, остановки и запрета повторной отправки; в QEMU проверяется модель отказов без повреждения накопителя, реальная аппаратная инъекция и физические SSD отдельно;
- [ ] запуск PhoenixFS поверх NVMe в проверочном профиле.

### 5. Полноценная графика

- [ ] выбрать первый поддерживаемый физический графический профиль;
- [ ] реализовать штатный драйвер вместо постоянной зависимости от UEFI GOP;
- [ ] оставить GOP только для ранней загрузки и аварийной диагностики;
- [ ] определить общую графическую границу для последующего компоновщика.

### 6. Эталонный драйвер для комплекта разработки

- [ ] минимальный документированный драйвер;
- [ ] пример регистрации и подбора;
- [ ] пример DMA;
- [ ] пример прерываний;
- [ ] проверки совместимости версии интерфейса.

### 7. Зачистка устаревших рабочих путей

- [ ] убрать рабочую зависимость от xAPIC там, где выбран x2APIC;
- [ ] не использовать PIC 8259 как рабочий контроллер;
- [ ] не добавлять BIOS/CSM;
- [ ] не добавлять IDE/PATA и старые USB-контроллеры;
- [ ] оставить только безопасное отключение наследуемых блоков, если это требуется современной платформой.
