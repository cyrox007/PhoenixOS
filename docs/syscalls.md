# ABI системных вызовов

Этап 0.1 начинает вход в системные вызовы с отдельного языка-независимого контракта. Аппаратный вход `SYSCALL` уже исполняется в контролируемой проверке ядра; пользовательский переход и возврат `SYSRET` остаются следующим этапом.

## Версия

Текущий экспериментальный ABI имеет версию `0`. Номера конкретных системных вызовов ещё не объявлены стабильными. После перехода публичных интерфейсов из экспериментального состояния несовместимые изменения потребуют новой версии ABI.

## x86-64: вход

При выполнении системного вызова регистры интерпретируются так:

- `RAX` — номер системного вызова;
- `RDI` — аргумент 0;
- `RSI` — аргумент 1;
- `RDX` — аргумент 2;
- `R10` — аргумент 3;
- `R8` — аргумент 4;
- `R9` — аргумент 5.

`RCX` и `R11` не используются для аргументов, потому что механизм x86-64 `SYSCALL/SYSRET` использует их для адреса возврата и флагов.

## x86-64: результат

Возврат использует два регистра:

- `RAX` — 64-битное значение результата;
- `RDX` — статус.

Статус `0` означает успех. Ненулевое значение — код ошибки. Отдельный статус сохраняет полное 64-битное пространство значения и не требует резервировать отрицательный диапазон.

## Представление

Crate `phoenix-syscall-abi` работает без стандартной библиотеки и определяет `#[repr(C)]` структуры `SyscallRequest` и `SyscallReturn`, а также прозрачный статус. Эти типы служат эталонным описанием контракта и тестируются независимо от ядра.

## Настройка аппаратного пути

Ядро проверяет расширенный CPUID-бит `SYSCALL/SYSRET`. При наличии поддержки настраиваются:

- `IA32_STAR` — селектор кода ядра для входа;
- `IA32_LSTAR` — адрес точки входа;
- `IA32_FMASK` — маска, очищающая TF, IF и DF на входе;
- `IA32_EFER.SCE` — разрешение механизма системных вызовов.

После записи все MSR читаются обратно и проверяются. `LSTAR` указывает на минимальную точку входа: она сохраняет `RCX` и `R11`, собирает запрос из регистров ABI, вызывает диспетчер ядра, помещает значение результата в `RAX`, статус в `RDX` и возвращается в контролируемую точку проверки. QEMU выполняет настоящую инструкцию `SYSCALL` и проверяет номер вызова, все шесть аргументов и результат. Успех подтверждается маркерами `syscall msr self-test: OK` и `syscall entry self-test: OK`.

Для операций с пользовательской памятью диспетчер получает адресное пространство из контекста текущего процесса. Контекст устанавливается перед входом в CPL3 и снимается после возврата; ранний однопроцессорный путь делает это при запрещённых прерываниях. IPC copy-in/copy-out поэтому проверяет реальные отображения именно вызывающего процесса, а не разыменовывает пользовательский указатель в адресном пространстве ядра.

Тот же контекст предоставляет таблицу возможностей процесса и общий фиксированный реестр endpoint-объектов. Неблокирующие `ipc_send`/`ipc_receive` выполняют настоящие операции очереди после проверки прав и пользовательских буферов. `ipc_receive` возвращает число слов в `RAX`, а в пользовательскую структуру метаданных записывает идентификатор отправителя, фактическую длину и переданный capability handle либо `u64::MAX`.

## Пользовательские сегменты

GDT содержит отдельные сегменты данных и кода уровня привилегий 3. Они расположены в порядке, совместимом с аппаратной формулой возврата `SYSRET`: верхняя половина `IA32_STAR` задаёт основу, из которой процессор получает пользовательские `SS` и `CS`.

При загрузке ядро проверяет, что фактические селекторы GDT совпадают со значениями, которые получит процессор из `IA32_STAR`. Успешная проверка выводит маркер `syscall user selectors self-test: OK`.

## Стек входа

Инструкция `SYSCALL` не меняет `RSP`, поэтому точка входа сразу сохраняет исходный указатель стека и переключается на отдельный ранний стек ядра размером 64 КиБ. Только после этого она размещает сохранённые регистры и вызывает диспетчер Rust.

QEMU проверяет, что исходный `RSP` сохранён, обработчик действительно выполнялся внутри отдельного диапазона стека и перед возвратом исходный стек был восстановлен. Успех подтверждается маркером `syscall entry stack self-test: OK`.

До смены стека `IA32_FMASK` уже очищает флаг разрешения обычных маскируемых прерываний, поэтому короткий участок сохранения исходного `RSP` не прерывается обычным аппаратным IRQ.

Текущий стек один на систему и предназначен только для раннего однопроцессорного этапа. Перед многопроцессорностью и параллельными системными вызовами он должен стать отдельным для каждого процессора или исполняемого потока.

## Контекст возврата

Перед будущим `SYSRET` ядро формирует явный `UserReturnContext` с пользовательскими `RIP`, `RSP` и `RFLAGS`. Проверка адресов опирается на текущее раннее окно процесса P4[0], поэтому расширение пользовательского пространства потребует согласованного изменения этой границы. Контекст отклоняется, если адрес инструкции или стека равен нулю, выходит за раннее пользовательское окно P4[0] либо содержит флаги IOPL, NT, RF или VM.

Обязательный бит 1 в `RFLAGS` нормализуется ядром. QEMU проверяет допустимый контекст и набор заведомо недопустимых вариантов; успешный путь подтверждается маркером `syscall return context self-test: OK`.

## Стек смены привилегий

TSS содержит отдельный 64-КиБ стек уровня привилегий 0. Он не используется самой инструкцией `SYSCALL`, но необходим для безопасного перехода на стек ядра, если исключение или обычное аппаратное прерывание возникнет во время выполнения пользовательского кода.

Этот стек отделён от стека точки входа системного вызова и от IST-стека двойного сбоя. При загрузке ядро проверяет его размер и выравнивание; успешный путь подтверждается маркером `user privilege stack self-test: OK`.

## Первый пользовательский цикл

Самопроверка создаёт настоящее адресное пространство процесса с отдельной исполняемой пользовательской страницей и отдельным пользовательским стеком. Машинный код самопроверки загружается через физическое отображение ядра, после чего процессный CR3 временно становится активным.

Переход из ядра в пользовательский режим выполняется через `iretq` с сегментами уровня привилегий 3. Пользовательский код выполняет настоящий `SYSCALL`, проверяет возвращённые значение и статус, а также подтверждает, что `CS` и `SS` имеют уровень привилегий 3. Обычный возврат из системного вызова выполняется через `SYSRETQ`.

Для завершения только этой ранней самопроверки используется временный служебный номер системного вызова, который возвращает выполнение в сохранённую контрольную точку ядра. Он не входит в стабильный ABI приложений и должен быть удалён после появления штатной модели завершения пользовательского потока.

Проверка выполняется с отключёнными обычными аппаратными прерываниями, чтобы первый переход уровня привилегий не зависел от ещё незавершённого вытеснения пользовательских потоков. После возврата адресное пространство уничтожается, а распределитель обязан получить обратно все выделенные страницы.

Успешный путь подтверждается маркером `user mode syscall self-test: OK`.

## Текущее ограничение и следующий инкремент

Аппаратный вход, пользовательские сегменты, стек системного вызова, TSS-стек смены привилегий и первый контролируемый цикл CPL3/SYSCALL/SYSRET уже связаны с реальным адресным пространством процесса. Следующий шаг — заменить служебное завершение самопроверки штатным жизненным циклом пользовательского потока и затем закрепить первые реальные номера системных вызовов.
