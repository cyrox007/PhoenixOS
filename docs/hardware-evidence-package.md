# Пакет аппаратных доказательств PhoenixOS 0.3

## До загрузки ASUS

В Windows 10 предусмотрен один пассивный сбор сведений об оборудовании:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-asus-evidence.ps1
```

В текущем каталоге создаётся файл `PhoenixOS-ASUS-Windows-evidence.txt`.
Скрипт читает модель компьютера, версию UEFI, параметры ЦП, перечень
PCI VID/PID, модели накопителей и доступный статус BitLocker. Он не собирает
ключи, серийные номера и индивидуальные идентификаторы экземпляров.
Выполнение в Windows пока не подтверждено реальным запуском. Скрипт
не делает записи в конфигурацию устройств; создаёт только текстовый отчёт.

## После пассивной диагностической загрузки

Только независимый `phoenixos-diagnostic-uefi.img` предназначен для ASUS.
Штатный `phoenixos-uefi.img` запускать на ноутбуке запрещено.

Журнал после транскрипции видеозаписи или сохранения из последовательного
порта анализируется командой:

```sh
python3 scripts/evaluate-dma-evidence.py diagnostic-report.txt
```

Обработчик проверяет один, **последний** диагностический запуск: карту памяти,
постраничный аудит прямого отображения, псевдонимы текущей CR3, целостность
структуры IVRS, запрет DMA и отметку завершения без переполнения.
Нельзя соединять успешные строки из нескольких запусков.
Неполный журнал приводит к коду завершения 2.

Сам по себе отчёт QEMU, текстовая транскрипция или набор признаков
`complete=true` **не доказывают**, что данные получены с ASUS.
Обработчик никогда не закрывает аппаратные 16/17 и 17/17: отсутствуют
доказательства для других ядер и CR3, действительной изоляции IOMMU,
выбранного контроллера и реального завершённого DMA.

Текущий аппаратный показатель остаётся **15/17**.
