# Виртуальная память

PhoenixOS отделяет работу с таблицами страниц от конкретного загрузчика.

## Доступ к таблицам страниц

На раннем этапе загрузчик создаёт внутреннее линейное отображение физической памяти в адресное пространство ядра.

Конфигурация ядра запрашивает это отображение через `BootloaderConfig`. В `phoenix-vm` передаётся только полученное виртуальное смещение, поэтому сама библиотека не зависит от `BootInfo` и конкретного загрузчика.

Через смещение библиотека получает активную таблицу P4 из CR3 и создаёт `OffsetPageTable`.

## Правила владения

Изменяемый доступ к активной P4 должен иметь единственного владельца.

Создание двух независимых `ActivePageTable` для одной таблицы нарушает модель владения и может повредить отображения. Поэтому конструктор является `unsafe` и требует явного подтверждения этого условия.

Системный распределитель физической памяти также создаётся один раз и используется как единственный источник новых физических страниц и таблиц страниц.

## Базовые операции

Первый интерфейс предоставляет:

- отображение одной страницы 4 КиБ;
- снятие отображения;
- преобразование виртуального адреса в физический;
- вычисление диапазона страниц для произвольного диапазона байтов.

После изменения таблицы выполняется обязательный сброс соответствующей записи TLB.

## Проверка в реальном ядре

Автоматическая загрузка QEMU выполняет полный цикл:

1. создаёт системный распределитель из реальной карты памяти UEFI;
2. получает физическое смещение от загрузчика;
3. создаёт единственный `ActivePageTable`;
4. выделяет физическую страницу;
5. отображает её на зарезервированный тестовый виртуальный адрес;
6. записывает и читает контрольное 64-битное значение;
7. проверяет обратное преобразование виртуального адреса;
8. снимает отображение;
9. возвращает целевую физическую страницу распределителю;
10. выводит маркер `virtual memory self-test: OK`.

CI требует одновременно увидеть маркер проверки исключений и маркер виртуальной памяти.

## Текущее ограничение

При первом отображении новой области x86-64 требует промежуточные таблицы страниц. Они также выделяются системным распределителем.

Текущая операция снятия одного отображения возвращает целевой кадр, но намеренно не уничтожает пустые промежуточные таблицы. Их рекурсивное освобождение будет добавлено вместе с управлением адресными пространствами и долговременным учётом таблиц страниц.

## Следующие шаги

После подтверждённой виртуальной памяти:

- зафиксировать область кучи ядра;
- отобразить её страницы;
- подключить ранний глобальный распределитель;
- добавить защитные страницы;
- определить постоянную схему виртуальных адресов ядра;
- затем перейти к отдельным адресным пространствам процессов.

Линейное отображение физической памяти остаётся внутренним механизмом ядра и не должно быть доступно пользовательским процессам.
