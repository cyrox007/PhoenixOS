# Куча ядра

После появления проверенных физических и виртуальных страниц PhoenixOS создаёт постоянную область кучи ядра.

## Размещение

Начальная область:

- виртуальный адрес: `0x0000_5000_0000_0000`;
- размер: 1 МиБ;
- страницы: 4 КиБ;
- права: запись разрешена, исполнение запрещено.

Перед запуском распределителя каждая страница кучи получает отдельный физический кадр через системный распределитель и отображается через `phoenix-vm`.

Если отображение очередной страницы не удаётся, уже созданные целевые отображения снимаются, а их физические кадры возвращаются.

## Первый алгоритм

Для первой рабочей кучи используется `linked_list_allocator` версии 0.10.6.

Он подходит для раннего этапа, потому что:

- работает без стандартной библиотеки;
- не требует отдельной памяти для собственной структуры;
- умеет освобождать и объединять свободные блоки;
- имеет небольшой и понятный интерфейс.

Это **не окончательный алгоритм** PhoenixOS. Поиск подходящего свободного блока линейный по числу свободных участков, поэтому после появления реальных нагрузок планируется переход на размерные классы, слэбы или гибридную схему для горячих путей ядра.

Публичные пользователи кучи не должны зависеть от конкретного алгоритма.

## Проверка

После инициализации ядро реально использует глобальный распределитель:

1. создаёт `Box<u64>`;
2. создаёт и заполняет `Vec<u64>`;
3. проверяет сохранность значений;
4. проверяет рост занятой памяти;
5. освобождает оба объекта;
6. проверяет возврат занятой памяти к начальному уровню;
7. выводит `kernel heap self-test: OK`.

CI требует этот маркер вместе с успешной проверкой исключений и виртуальной памяти.

## Дальнейшее развитие

- защитные страницы вокруг кучи;
- возможность наращивания области;
- отдельные быстрые классы для небольших объектов;
- статистика фрагментации;
- отладочный режим с заполнением освобождённой памяти;
- проверка утечек в тестовых сборках;
- отдельные пулы для объектов ядра, где это оправдано измерениями.
