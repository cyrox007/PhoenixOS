# Локальный APIC и системные тики

На этапе 0.1 PhoenixOS использует локальный контроллер прерываний процессора как источник периодических системных тиков.

## Поддерживаемые режимы

Ядро сначала проверяет наличие локального APIC через CPUID. После этого выбирается наиболее подходящий режим:

- x2APIC, если процессор объявляет его поддержку;
- обычный xAPIC как запасной путь для совместимых процессоров без x2APIC.

Устаревшие контроллеры 8259 маскируются до разрешения аппаратных прерываний.

Для xAPIC физическая страница регистров локального контроллера берётся из IA32_APIC_BASE и постоянно отображается в отдельную область виртуального адресного пространства ядра как некэшируемая память устройств.

## Таймер

Для периодического таймера используется вектор `0xe0`, для ложных прерываний — `0xff`.

В обоих режимах ядро:

- включает локальный APIC;
- задаёт делитель таймера;
- переводит таймер в периодический режим;
- ведёт атомарный 64-разрядный счётчик тиков;
- подтверждает каждое таймерное прерывание через EOI.

Текущий делитель равен единице, начальное значение счётчика таймера — `10_000_000`.

Системный тик на этом этапе является внутренним событием планирования. Он пока не используется как единица календарного или монотонного времени.

## Проверка при загрузке

После инициализации памяти и кучи ядро запускает локальный таймер, разрешает прерывания и ожидает не менее трёх аппаратных тиков.

Успешный путь выводит выбранный режим локального APIC и строку:

`apic timer self-test: OK`

Автоматическая загрузка QEMU требует этот маркер вместе с уже существующими проверками исключений, виртуальной памяти и кучи.

Базовая конфигурация QEMU намеренно не требует x2APIC: таким образом регулярно проверяется запасной путь обычного xAPIC. Путь x2APIC использует тот же интерфейс тиков и выбирается автоматически на оборудовании, где он доступен.

## Границы текущего этапа

Реализация даёт планировщику стабильный периодический источник прерываний и не привязывает его к одному режиму локального APIC.

Калибровка тиков в единицы времени, выбор эталонного источника времени, чтение таблиц ACPI и маршрутизация внешних прерываний через ввод-вывод APIC относятся к последующим аппаратным подсистемам.
