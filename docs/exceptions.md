# Исключения процессора

PhoenixOS устанавливает собственные таблицы GDT и IDT до запуска подсистем, которые могут активно работать с памятью, таймерами и драйверами.

## Что реализовано

На этапе 0.1 ядро выполняет:

- загрузку собственной GDT;
- установку TSS;
- выделение отдельного стека IST для двойного сбоя;
- загрузку IDT;
- обработку точки останова;
- аварийную обработку неверной инструкции;
- аварийную обработку нарушения общей защиты;
- аварийную обработку ошибки страницы;
- аварийную обработку двойного сбоя.

Критические обработчики используют ранний последовательный канал и не требуют кучи, файловой системы, планировщика или пользовательского пространства.

## Отдельный стек двойного сбоя

Двойной сбой может возникнуть, когда процессор уже не способен корректно использовать текущий стек. Поэтому запись IDT для двойного сбоя переключается на отдельный стек через IST в TSS.

Это не заменяет будущие отдельные стеки прерываний и ядра для потоков.

## Проверка в CI

После загрузки IDT ядро намеренно выполняет `int3`. Обработчик точки останова должен:

1. получить управление;
2. записать в последовательный журнал маркер `exception: breakpoint`;
3. вернуть управление в основной путь загрузки.

Сценарий QEMU проверяет наличие этого маркера и финального `bootstrap: OK`. Поэтому успешная сборка сама по себе больше не считается достаточной проверкой таблицы исключений.

## Следующие шаги

- добавить тестовый режим для заведомо аварийных исключений;
- вывести ошибку страницы вместе с адресом CR2;
- связать исключения с будущим аварийным экраном framebuffer;
- добавить машинно-читаемую структуру аварийного отчёта;
- после появления процессов различать исключения ядра и пользовательских процессов.
