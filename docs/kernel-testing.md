# Инфраструктура проверок ядра

PhoenixOS использует два уровня автоматических проверок раннего ядра:

- модульные проверки библиотек, которые можно выполнить на основной системе сборки;
- проверочную загрузку UEFI-образа в QEMU/OVMF с анализом последовательного вывода.

## Реестр загрузочных проверок

Обязательные признаки успешной загрузки хранятся в файле `tests/qemu/bootstrap.markers`.

Каждая непустая строка, не начинающаяся с `#`, считается обязательным фрагментом последовательного журнала. Благодаря этому новая самопроверка ядра добавляется одной строкой в реестр и не требует расширять набор переменных среды в сценарии запуска.

Сценарий `scripts/check-serial-markers.sh` проверяет реестр против сохранённого последовательного журнала и завершает проверку ошибкой, если хотя бы один обязательный маркер отсутствует.

## Самопроверка инфраструктуры

Сценарий `scripts/test-check-serial-markers.sh` отдельно проверяет сам механизм:

- успешный журнал со всеми ожидаемыми строками принимается;
- комментарии и пустые строки игнорируются;
- отсутствие обязательной строки обязательно приводит к ошибке.

Эта проверка выполняется в CI до сборки UEFI-образа.

## Проверочная загрузка

`scripts/run-qemu-ci.sh`:

1. находит OVMF;
2. запускает UEFI-образ в QEMU;
3. сохраняет последовательный вывод;
4. проверяет ожидаемый код завершения;
5. передаёт журнал общему проверяющему сценарию и реестру маркеров.

Файл реестра можно заменить через переменную `PHOENIXOS_MARKERS_FILE`. Это позволяет иметь отдельные наборы для загрузки, процессов, системных вызовов, драйверов и аварийных сценариев без копирования QEMU-раннера.

## Правило добавления проверки

Самопроверка ядра считается частью автоматического контроля только после того, как:

- она имеет однозначный маркер успешного выполнения;
- маркер добавлен в соответствующий файл реестра;
- проверка проходит при реальной загрузке QEMU;
- документация описывает, что именно подтверждает этот маркер.
