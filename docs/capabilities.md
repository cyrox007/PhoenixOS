# Дескрипторы и возможности

## Назначение

Пользовательский процесс PhoenixOS не должен получать прямой указатель на объект ядра. Доступ к процессам, потокам, памяти, каналам межпроцессного взаимодействия, файлам и устройствам выдаётся через таблицу возможностей процесса.

Возможность связывает объект ядра с разрешённым набором операций.

## Дескриптор

Публичный дескриптор состоит из двух частей:

- номера слота;
- поколения слота.

Поколение изменяется при отзыве возможности. Если слот позже переиспользован для другого объекта, старый дескриптор не становится действительным для нового объекта.

Это защищает от случайного повторного использования устаревших дескрипторов.

## Права

Начальный набор прав:

- чтение;
- запись;
- исполнение;
- отображение памяти;
- ожидание;
- сигнал;
- передача;
- создание производной возможности;
- управление.

Конкретный тип объекта может использовать только подходящее ему подмножество этих прав.

## Уменьшение прав

Производная возможность может получить только подмножество прав исходной возможности. Повысить права через копирование дескриптора нельзя.

Создание производной возможности дополнительно требует права на создание производной возможности.

## Передача

Передача возможности между процессами в будущем будет выполняться через IPC.

Базовая модель уже определяет операцию передачи с потреблением исходного дескриптора. Она разрешена только при наличии права передачи. Позже IPC сможет использовать этот примитив для атомарного перемещения возможности из таблицы отправителя в таблицу получателя.

## Отзыв

Отзыв удаляет возможность из таблицы и увеличивает поколение слота. После этого старый дескриптор недействителен.

Первый инкремент не реализует дерево рекурсивного отзыва всех производных возможностей. Эта возможность будет добавлена отдельно, если модель IPC и разделяемых ресурсов подтвердит такую необходимость.

## Таблица процесса

Модель процесса содержит отдельный набор возможностей с явным владельцем `ProcessId`. Операции чтения, проверки прав, создания производной возможности и отзыва выполняются только через эту таблицу.

Передача между двумя таблицами выполняется атомарно относительно модели: сначала проверяются право передачи, действительность исходного дескриптора, возможность увеличить поколение и наличие места у получателя. Если получатель заполнен, исходный дескриптор остаётся действительным. При успехе у получателя появляется новый дескриптор, а исходный становится недействительным.

Это поведение предназначено для будущей передачи возможностей через IPC.

## Интеграционная проверка ядра

Обязательная QEMU-проверка создаёт две таблицы возможностей с разными владельцами `ProcessId`. Ядро выдаёт исходную возможность конечной точки, создаёт производную возможность только для чтения, проверяет запрет записи, отзывает производный дескриптор и подтверждает его недействительность.

После этого исходная возможность передаётся второму процессу. Старый дескриптор отправителя обязан стать недействительным, а получатель должен получить тот же объект с исходными разрешёнными правами. Успех подтверждается маркером `process capability self-test: OK`.

## Граница ядра

Библиотека `phoenix-capability` не зависит от конкретных объектов ядра и работает без стандартной библиотеки. Процессная оболочка находится в `phoenix-process`, а интеграционная проверка выполняется самим ядром.

Следующий шаг — использовать проверенные таблицы возможностей в пользовательских системных вызовах IPC.
