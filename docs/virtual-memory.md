# Виртуальная память

PhoenixOS отделяет работу с таблицами страниц от конкретного загрузчика.

## Ранний доступ

На раннем этапе загрузчик предоставляет линейное отображение физической памяти в виртуальное адресное пространство ядра.

Ядро передаёт в `phoenix-vm` только физическое смещение этого отображения. Библиотека не знает о структуре `BootInfo` и поэтому не привязана к одному способу загрузки.

Через смещение библиотека получает активную таблицу P4 из CR3 и создаёт `OffsetPageTable`.

## Правила владения

Изменяемый доступ к активной P4 должен иметь единственного владельца.

Создание двух независимых `ActivePageTable` для одной и той же таблицы нарушит модель владения Rust и может привести к повреждению отображений. Поэтому конструктор является `unsafe` и явно фиксирует этот контракт.

## Базовые операции

Первый интерфейс предоставляет:

- отображение одной страницы 4 КиБ;
- снятие отображения;
- преобразование виртуального адреса в физический;
- вычисление диапазона страниц, покрывающего произвольный диапазон байтов.

После изменения таблицы выполняется обязательный сброс записи TLB для затронутой страницы.

## Следующая интеграция

Перед использованием в ядре необходимо:

1. включить у загрузчика отображение физической памяти;
2. проверить наличие переданного физического смещения;
3. создать единственный `ActivePageTable`;
4. получить кадры таблиц из системного распределителя физической памяти;
5. отобразить тестовую страницу в заранее зарезервированной области;
6. записать и прочитать контрольное значение;
7. снять отображение и вернуть физический кадр;
8. только после этого создавать постоянную кучу ядра.

## Будущая схема адресного пространства

Схема виртуальных адресов ядра, пользовательских процессов, общей памяти, отображённых файлов и устройств будет зафиксирована отдельным архитектурным решением до появления стабильного ABI.

Раннее линейное отображение физической памяти является внутренним механизмом ядра и не должно быть доступно пользовательским процессам.
