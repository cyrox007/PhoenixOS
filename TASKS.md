## Ближайшая задача

### 1. Интерфейс DMA с заделом на IOMMU

Цель — дать драйверам единый безопасный способ получать память для обмена с устройствами, не связывая конкретный драйвер с текущей схемой физической памяти.

Критерии готовности:

- [ ] отдельный `no_std`-интерфейс DMA;
- [ ] явное различение процессорского виртуального адреса и адреса, видимого устройству;
- [ ] проверяемые размеры, выравнивание и границы;
- [ ] поддержка согласованного выделения/освобождения буфера без скрытой кучи на критическом пути;
- [ ] возможность позднее подставить преобразование адресов IOMMU без изменения интерфейсов драйверов;
- [ ] интеграционная проверка с текущим реестром драйверов;
- [ ] модульные проверки ошибочных размеров, переполнений и повторного освобождения;
- [ ] обновление `STATUS.md` и `ROADMAP.md`.

### 4. NVMe

- [ ] обнаружение контроллера через PCIe;
- [ ] очереди команд и завершений через общий DMA;
- [ ] чтение/запись блоков;
- [ ] подключение к `BlockDevice`;
- [ ] проверка ошибок и таймаутов;
- [ ] запуск PhoenixFS поверх NVMe в проверочном профиле.

### 5. Полноценная графика

- [ ] выбрать первый поддерживаемый физический графический профиль;
- [ ] реализовать штатный драйвер вместо постоянной зависимости от UEFI GOP;
- [ ] оставить GOP только для ранней загрузки и аварийной диагностики;
- [ ] определить общую графическую границу для последующего компоновщика.

### 6. Эталонный драйвер для комплекта разработки

- [ ] минимальный документированный драйвер;
- [ ] пример регистрации и подбора;
- [ ] пример DMA;
- [ ] пример прерываний;
- [ ] проверки совместимости версии интерфейса.

### 7. Зачистка устаревших рабочих путей

- [ ] убрать рабочую зависимость от xAPIC там, где выбран x2APIC;
- [ ] не использовать PIC 8259 как рабочий контроллер;
- [ ] не добавлять BIOS/CSM;
- [ ] не добавлять IDE/PATA и старые USB-контроллеры;
- [ ] оставить только безопасное отключение наследуемых блоков, если это требуется современной платформой.

## Правило выполнения

Каждая задача выполняется отдельной небольшой веткой. До слияния обязательны профильные тесты, затем полная автоматическая проверка. Если изменение меняет фактическую границу этапа, одновременно обновляются `TASKS.md`, `ROADMAP.md` и `STATUS.md`.
