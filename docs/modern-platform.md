# Проверенная политика современной платформы PhoenixOS 0.3

## Состав эталонной платформы

PhoenixOS ориентирована на **UEFI, ACPI, PCIe ECAM, x2APIC, NVMe и USB xHCI**. В проверочном QEMU/KVM используются только эти штатные пути и необходимые виртуальные устройства: выделенный NVMe-контроллер для загрузки, отдельный NVMe для PhoenixFS, xHCI с USB-клавиатурой и мышью, VirtIO-GPU и учебный контроллер EDU.

Этот документ фиксирует результат зачистки устаревших путей. **Он не утверждает, что современные материнские платы физически лишены всех унаследованных блоков:** важна невозможность выбрать их рабочими драйверами, а не сокрытие PCI-функций.

## Пять критериев этапа 0.3

### 1. Только x2APIC

Ядро проверяет аппаратные возможности CPUID, программирует x2APIC через MSR и **подтверждает** реальное включение режима, разрешённый вектор ложных прерываний и периодический таймер по значениям считанных MSR. Для процессоров без x2APIC возвращается ошибка; возврата к MMIO xAPIC нет. Таймер использует вектор `0xe0`; учебный MSI EDU использует вектор `0xe1` и завершает прерывание через x2APIC EOI.

### 2. PIC 8259 не используется как действующий контроллер

Маски `0x21` и `0xa1` записываются значением `0xff` только с запрещёнными прерываниями, затем **проверяются чтением**. Ядро не перенастраивает PIC для рабочих прерываний, не назначает ему векторы и не отправляет ему EOI. Если маска не подтверждена, современный путь таймера не запускается.

Это **безопасное отключение**, а не утверждение о физическом отсутствии PIC на плате.

### 3. Только UEFI, без BIOS/CSM

Сборщик `build.rs` создаёт образ через `bootloader::UefiBoot`. QEMU загружает OVMF с двумя явными областями `pflash` (код прошивки — только чтение; переменные — отдельная временная копия). Нет `-bios`, старого загрузочного диска через `-hda` и резервного CSM.

Важное исправление: ранее загрузочный образ подключался параметром `-drive format=raw,file=...` **без интерфейса** и мог попасть на неявную IDE-шину. Теперь используется `-drive if=none,...,id=phoenix-boot` плюс отдельное устройство `nvme,drive=phoenix-boot,bootindex=1`. Установлен `-nodefaults`, чтобы QEMU не добавлял неявные старые устройства из типовых настроек. Загрузочный образ доступен прошивке через NVMe, без старой шины IDE.

### 4. Ни IDE/PATA, ни старые USB-контроллеры не получают драйверов

Модуль `phoenix_pcie::modern_profile` по действительным кодам классов PCI различает:

| Класс | Идентификатор | Решение |
|---|---|---|
| IDE/PATA | `01:01:xx` | Не назначать рабочий драйвер |
| UHCI | `0C:03:00` | Не назначать рабочий драйвер |
| OHCI | `0C:03:10` | Не назначать рабочий драйвер |
| EHCI | `0C:03:20` | Не назначать рабочий драйвер |
| NVMe | `01:08:02` | Рабочий путь NVMe |
| xHCI | `0C:03:30` | Рабочий путь xHCI |

Платформенное перечисление собирает `LegacyPciAudit` и принимает решение об инициализации NVMe/xHCI **через общий фильтр**. Наличие старого класса не приводит к чтению его BAR, созданию DMA-очереди или включению Bus Master. Число обнаруженных старых функций журналируется отдельно; оно может быть больше нуля из-за чипсета. Остальные типы PCI (например, GPU или EDU) продолжают обрабатываться собственными проверенными подсистемами.

### 5. Наследуемое состояние допускает только безопасное отключение

Реализовано узкое наследуемое действие — маскирование PIC 8259 и проверка результата. Запрещено притворяться, что это также отключает физическое питание старого контроллера, переключает общий маршрут IRQ через IMCR или выполняет аппаратную передачу всех USB-портов: такой код требует отдельных подтверждённых профилей оборудования.

В тестовой QEMU-конфигурации `isa-debug-exit` сохраняется исключительно для сообщения кода завершения испытаний; это **не драйвер PIC или ISA-устройства в рабочей ОС**. Стандартный VGA нужен только для раннего GOP и аварийного экрана. Его наличие не является запасным полнофункциональным графическим стеком.

## Автоматические проверки

- `crates/pcie/src/modern_profile.rs`: модульные испытания IDE/PATA с разными интерфейсами, старых USB-классов, правильного NVMe/xHCI и отказа от подмены SATA/NVMe.
- `tests/platform/test-modern-profile.py`: реальные параметры запуска QEMU формируются одной функцией и проверяются перед запуском. Отрицательные испытания запрещают `-nodefaults` пропускать, добавлять `-bios`, `-hda`, IDE/PATA, UHCI/OHCI/EHCI и убирать обязательные UEFI, загрузочный NVMe, проверочный NVMe или xHCI.
- `tests/qemu/bootstrap.markers`: обязательные журнальные признаки реального выбора NVMe/xHCI и проверки x2APIC/PIC.
- Полная загрузка QEMU продолжает проверять прежние NVMe/PhoenixFS, USB HID, VirtIO-GPU, EDU с MSI и пользовательское пространство.

Ожидаемые признаки ядра:

```text
modern pci policy: OK nvme=1 xhci=1
modern interrupt mode: OK apic=x2APIC pic_mask=ffff
```

Для самостоятельного запуска проверок параметров достаточно:

```sh
python3 tests/platform/test-modern-profile.py
```

Полные аппаратные испытания требуют эталонной инфраструктуры QEMU/KVM и OVMF, настроенной в `.github/workflows/ci.yml`.

## Что не проверено

- Физические контроллеры ASUS VivoBook, их прошивки и фактическая маршрутизация линий IRQ.
- Варианты устройств с неполными таблицами ACPI или без x2APIC. Система в таком случае **должна отказывать безопасно**, а не запускаться на PIC/xAPIC.
- Отдельный аппаратный IOMMU и защита DMA от злонамеренных устройств. Интерфейсные критерии DMA закрыты на `8/8` после реализации сменяемого механизма адресации, **но аппаратное преобразование и испытания PAT/MTRR остаются открытыми**.
- Выключение через конфигурационные регистры конкретных унаследованных мостов: оно сознательно не выполнялось во избежание риска физическому оборудованию.

Все пять критериев зачистки выполнены (`5/5`). После отдельной реализации сменяемой адресации DMA исходный перечень этапа 0.3 составляет **43/43 (100,0 %)**. Это программная и виртуальная приёмка; реальные IOMMU, PAT/MTRR и физические контроллеры остаются **непроверенными**. Последующая сверка и ограничения отражены в [акте аудита](audit-0.3.md).
