# Аварийное восстановление зашифрованного хранилища

Этот документ уточняет D-011 и D-016. Цель — сохранить сильное шифрование данных и одновременно не превращать отказ одного компонента компьютера в необратимую потерю исправных данных.

## Что именно должна переживать система

Аварийное восстановление рассчитано на случаи, когда:

- основная PhoenixOS не загружается;
- повреждён загрузчик или системный раздел;
- заменена системная плата;
- аппаратный модуль доверия недоступен или потерял состояние;
- сломан обычный путь разблокировки;
- повреждена одна копия служебных метаданных зашифрованного тома;
- данные требуется перенести на другой компьютер или новый накопитель.

Оно не может восстановить блоки, которые физически перестали читаться. Отказ самого накопителя покрывается только отдельными резервными копиями.

## Модель ключей

Для каждого зашифрованного тома создаётся случайный ключ данных. Данные тома шифруются только им.

Ключ данных хранится на накопителе только в защищённых оболочках. Один том может одновременно иметь несколько оболочек:

1. оболочка от пользовательской парольной фразы;
2. оболочка, связанная с аппаратным модулем доверия;
3. оболочка от аварийного ключа восстановления;
4. позднее — дополнительные организационные оболочки, если пользователь явно их включил.

Удаление одной оболочки не уничтожает остальные. Замена пароля или аварийного ключа не требует перешифровывать весь том.

## Аварийный ключ

Аварийный ключ:

- создаётся локально;
- уникален для конкретного тома или явно выбранной группы томов;
- никогда не является общим мастер-ключом PhoenixOS;
- не отправляется разработчикам;
- не требует подключения к сети;
- может быть сохранён на отдельной флешке, другом доверенном устройстве или распечатан;
- может быть заменён и отозван после успешной обычной разблокировки либо после подтверждённого аварийного восстановления.

При включении полного шифрования интерфейс должен настойчиво предложить создать хотя бы один независимый путь восстановления и проверить его до завершения настройки.

## Среда восстановления

Среда восстановления — отдельная минимальная подписанная система, не зависящая от исправности основной установки.

Основной сценарий:

1. пользователь загружает среду восстановления;
2. среда обнаруживает зашифрованные тома;
3. пользователь выбирает том и способ разблокировки;
4. при аварийной разблокировке вводится ключ восстановления;
5. сначала выполняется проверка служебных метаданных и доступности блоков;
6. том по умолчанию открывается только для чтения;
7. пользователь может выбрать файлы либо весь том для копирования на другой носитель;
8. записывающие операции включаются отдельно и требуют явного подтверждения.

Среда восстановления не должна автоматически подключаться к сети, отправлять телеметрию или пытаться получить удалённый ключ.

## Защита служебных метаданных

Критические данные, необходимые для разблокировки тома, должны иметь:

- несколько копий в разных областях носителя;
- контроль целостности;
- номер версии формата;
- идентификатор тома;
- сведения о доступных ключевых оболочках;
- защиту от незаметной подмены;
- возможность определить, какая копия повреждена.

Если одна копия повреждена, исправная копия используется для чтения. Восстановление повреждённой копии выполняется только после успешной проверки тома.

## Режим безопасного спасения данных

Для неисправного или нестабильного накопителя среда восстановления должна иметь отдельный режим спасения:

- никаких фоновых записей на исходный носитель;
- повторное чтение проблемных блоков с ограниченным числом попыток;
- последовательное копирование читаемых областей на другой носитель;
- журнал карты прочитанных и непрочитанных областей;
- возможность продолжить прерванное копирование;
- работа с копией образа вместо оригинала после завершения первичного спасения.

Файловое восстановление и исправление структуры выполняются уже над копией, когда это возможно.

## Резервные копии

Аварийный ключ защищает от потери доступа к исправным зашифрованным данным, но не от гибели накопителя.

Поэтому PhoenixOS должна поддерживать:

- зашифрованные резервные копии на внешний носитель;
- возможность иметь независимый ключ восстановления резервной копии;
- версионные снимки;
- проверку целостности после создания копии;
- периодическую пробную проверку восстановления;
- понятный статус: когда была последняя успешная копия и когда она последний раз проверялась.

Резервная копия не считается надёжной только по факту успешной записи. Она считается проверенной после чтения и проверки структуры.

## Запрещённые решения

Не допускаются:

- универсальный мастер-ключ PhoenixOS;
- скрытая оболочка ключа, неизвестная владельцу;
- обязательное обращение к серверу для аварийного доступа;
- автоматическая отправка ключа восстановления;
- автоматическая запись на повреждённый исходный накопитель;
- обещание восстановления при физической утрате всех копий данных.

## Будущие проверки

До выпуска 1.0 должны существовать воспроизводимые сценарии:

- потеря аппаратного модуля доверия при исправном накопителе;
- замена системной платы;
- повреждение основной системы;
- повреждение одной копии метаданных разблокировки;
- отзыв старого аварийного ключа и выпуск нового;
- экспорт данных из среды восстановления только для чтения;
- восстановление после прерванного копирования;
- восстановление зашифрованной резервной копии на чистый накопитель.
