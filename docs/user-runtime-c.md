# C-совместимая файловая среда

Первый C-совместимый слой PhoenixOS находится в `phoenix-user-runtime` и объявлен в `sdk/include/phoenix/runtime.h`.

## Результат вызова

Каждая файловая функция возвращает `PhoenixRuntimeCallResult` из двух 64-разрядных полей:

- `value` — значение успешной операции;
- `status` — ноль при успехе или код ошибки системного вызова.

Такой формат сохраняет полное 64-разрядное значение и не использует отрицательные числа как скрытый канал ошибок.

## Дескриптор

`PhoenixFileDescriptor` состоит из 32-разрядного номера слота и 32-разрядного поколения. Его расположение совпадает со стабильным `PackedFileDescriptor` системного ABI.

## Пути и буферы

Путь передаётся как указатель и явная длина. Завершающий нулевой байт не требуется. Буферы чтения и записи также передаются указателем и длиной. Среда выполнения не разыменовывает эти указатели: она передаёт адреса ядру, а ядро проверяет диапазон в адресном пространстве текущего процесса согласно D-014.

## Сопоставление errno

`phoenix_errno_from_status` преобразует публичные коды системного ABI в базовые номера ошибок C/POSIX без хранения глобального состояния: неизвестный вызов → `ENOSYS` (38), неверные аргументы → `EINVAL` (22), временная неготовность операции → `EAGAIN` (11), неизвестный ненулевой статус → `EIO` (5). Нулевой статус преобразуется в 0.

Функция намеренно не устанавливает глобальный `errno`: потокобезопасное хранение ошибки появится вместе с пользовательскими потоками и полноценным слоем `libc`.

## Текущий объём

Доступны `phoenix_file_open`, `phoenix_file_read`, `phoenix_file_write`, `phoenix_file_seek` и `phoenix_file_close`.

Это ещё не полная `libc`: отсутствуют `errno`, стандартные номера файловых дескрипторов, каталоговые операции, потоки ввода-вывода и POSIX-совместимые имена. Следующий слой должен строиться поверх этой стабильной границы, не дублируя системные вызовы.
