# Состояние PhoenixOS

## Текущий этап

**0.1 — Основы ядра**

Этап 0.0 завершён и подтверждён автоматическими проверками в `develop`.

Реализовано:

- ядро Rust `no_std` для x86-64;
- UEFI-образ и загрузка QEMU/OVMF;
- ранняя диагностика и аварийный вывод;
- GDT, TSS, IDT и обработка основных исключений;
- отдельный IST-стек двойного сбоя;
- проверка обработчика точки останова через реальный `int3`;
- ранний графический экран framebuffer;
- начальный и системный распределители физической памяти;
- базовое управление активными таблицами виртуальной памяти;
- модульные проверки низкоуровневых библиотек;
- публикация UEFI-образа результатом автоматической сборки.

## Проверка памяти в реальном ядре

Путь загрузки использует `SystemFrameAllocator` как единственного владельца свободных физических страниц.

Загрузчик предоставляет ядру внутреннее линейное отображение физической памяти. Через него `ActivePageTable` получает доступ к текущей P4.

QEMU-проверка выполняет:

1. выделение физической страницы;
2. отображение на зарезервированный виртуальный адрес;
3. запись и чтение контрольного значения;
4. проверку преобразования виртуального адреса;
5. снятие отображения;
6. возврат физической страницы.

Успешный путь обязан вывести `virtual memory self-test: OK`.

## Текущее ограничение

Промежуточные таблицы страниц, созданные при новом отображении, пока не освобождаются автоматически после удаления последнего дочернего отображения.

Это не мешает следующему этапу с постоянной кучей ядра, но будет устранено до появления множества динамических адресных пространств процессов.

## Следующие задачи

- отобразить постоянную область кучи ядра;
- подключить ранний глобальный распределитель;
- добавить защитные страницы вокруг критических областей;
- затем перейти к APIC и таймерам.

Системная физическая и виртуальная память считаются готовой основой только при зелёной интеграционной проверке QEMU этой ветки.
